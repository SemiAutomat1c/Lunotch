# Lunotch: local launch and interaction checks

This is a personal macOS fork of Boring Notch. A **Debug app** was rebuilt November 9 with an Apple Development signature (Team ID `233W7469MN`, bundle ID `dev.ryandeniega.lunotch`) and relaunched from Xcode DerivedData; at that verification its main PID was **67609**. That build includes the upstream icon/wording cleanup and compiled localizations. The **v0.1.0-preview.3 Release DMG** includes these features and the branding cleanup; it was built for arm64, ad-hoc signed, and passed DMG/signature checks. Switching between ad-hoc and development signatures with the same bundle identifier can affect screen-recording permission. The new capture path attempts a real ScreenCaptureKit still capture even if the older CoreGraphics preflight reports no permission, and shows the actual failure reason if it fails. Signing, build, and Debug relaunch passed; **the macOS permission result and actual selection/editor UI remain unverified**. Work Mode timer, RAM, browser Cancel and research-note Save/Append passed earlier live checks.

It runs in the menu bar/notch rather than as a normal Dock app. Quit the currently running **Lunotch** instance via its menu bar Quit command before launching another build to avoid two notch overlays. During the November 8 fix, the older PID 30256 ignored SIGTERM and required targeted SIGKILL before the new process launched. Only enable camera, calendar, Reminders, or Accessibility permissions if you want the corresponding features.

**Confirmed November 9 TCC identity mismatch:** At 00:33 PHT, macOS `tccd` logged `Failed to match existing code requirement for subject dev.ryandeniega.lunotch and service kTCCServiceScreenCapture`. The system TCC row said **allowed** (`auth_value=2`) but its saved requirement decoded to an old ad-hoc `cdhash`, whereas the currently running app uses an Apple Development certificate requirement. The enabled toggle therefore does not establish that the running binary is authorized. No TCC settings were changed during diagnosis.

**Manual recovery for this exact mismatch:** Quit all Lunotch instances from its menu bar Quit command. In Terminal, run `tccutil reset ScreenCapture dev.ryandeniega.lunotch` (resets **only Lunotch's screen-capture permission**). Reopen the **Apple Development-signed** Debug app from the path above, use **Capture Selection…**, and allow Screen & System Audio Recording access in the prompt or System Settings. If macOS requests a relaunch, fully quit and reopen Lunotch before trying Capture Selection again. If the command fails or access is still denied, use System Settings → Privacy & Security → Screen & System Audio Recording to remove the stale Lunotch permission entry, re-add the current app and retry. This step is for the user to perform, not an automated TCC reset. Until permission is re-granted and an actual capture succeeds, mark the capture flow unverified.

## Screenshot Studio Phase 1 manual QA

1. **Top-bar shortcut:** Expand the notch and click the top-left `camera.viewfinder` icon beside Home/Shelf. Verify the native selection crosshair appears without a right-click, including when the Shelf has no items. At **400 × 166 points**, make sure Home, Shelf and screenshot icons fit between the curved outer edge and physical camera cutout, with the 100% battery indicator clear on the right. Repeat at the 640pt layout and test each icon's click target and VoiceOver label.
2. **Open the editor:** Right-click the Lunotch notch → **Screenshot Studio** → **Open Image…** and select an image. Repeat using **Edit Image from Clipboard** after copying an image. Verify that a separate editor opens and music playback remains in the compact notch. The same actions should be available from the menu bar.
3. **Capture a selection:** Use the top-bar icon or **Capture Selection…** menu action. Lunotch uses **ScreenCaptureKit** for a still image of the display under the pointer, then shows its **own crosshair drag overlay**; it no longer launches `/usr/sbin/screencapture -i`. Drag an area and confirm the preview offers Edit/Copy/Dismiss; press Escape to cancel. Drag in reverse (bottom-right to top-left), test a Retina display, and test a second monitor if attached: the overlay and captured image must be from the **same screen**. The first capture may ask for **System Settings → Privacy & Security → Screen & System Audio Recording** access. After enabling it, fully quit and relaunch Lunotch. If permission appears enabled but capture is denied, follow the **confirmed TCC identity mismatch** recovery above. The error text should report the actual ScreenCaptureKit failure; if capture remains unavailable, try **Edit Image from Clipboard** or **Open Image…** and record the error. The old CLI's `could not create image from rect` failure prompted the original native capture change; real UI capture remains unverified.
4. **Enable optional auto-preview:** Choose **Choose Screenshot Folder…** and select the actual macOS screenshot-save folder. Take a standard `Command-Shift-4` screenshot; confirm a short-lived top-screen preview offers **Edit**, **Copy**, and **Dismiss**. Test a screenshot saved to a different folder (should not trigger a preview), disabling/re-enabling preview, and quitting/relaunching Lunotch to check folder-bookmark restoration. Confirm the app does not modify or delete the original screenshot.
5. **Edit:** On a disposable image, crop; draw with pen/highlighter; add arrows, rectangles, ellipses and text; change colors; place an opaque black redaction. Undo/Redo each action, including crop and clearing marks; check `Command-Z` / `Command-Shift-Z` and ensure a new edit after Undo invalidates Redo. Try the **Fit** button and 50%–400% zoom slider, scroll horizontally/vertically around a zoomed image, and draw/crop while zoomed; ensure annotations follow the image correctly. Verify precision on different image sizes and check that redaction is fully opaque in the exported image.
6. **Share and save:** Copy the edited image to clipboard and paste it into another app; export a PNG, reopen it, and confirm image dimensions, annotations, legibility and redaction match the editor. Cancel save/open dialogs to check graceful recovery.
7. **Regression:** Leave music playing and confirm focused Home remains **400 × 166 points** while Screenshot Studio opens/closes. Check notch hover, battery/header clearance, screenshot preview positioning, and return from full-width Shelf/Camera. Test Reduce Motion, dark/light appearance and external display if available. Note pass/fail and reproduction steps in `docs/GOAL.md`.
